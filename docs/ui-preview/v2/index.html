MTR NAVIGATION / REDESIGN PROPOSAL v2 — PROTOTYPE

站间物语 · 界面重设计雏形

布局与信息层级重设计提案。仅为设计讨论用的浏览器原型，示例数据，不连接服务器；不改动任何游戏代码。

02 — 设计雏形
展开：本提案的规划要点（现状问题 → 设计目标 → 逐屏改动 → 可实现性）

一、现状问题（来自现有 A 布局"铁路行程册"）

  • 顶栏拥挤：标题、三个页签、"更多"、关闭全部挤在一条木框横梁上，窄窗口下页签只剩 54px。
  • 层级扁平："查询"主按钮与"全部车站／定位／步行换乘"等三级工具视觉权重接近，主操作不突出。
  • 方案卡片密度高：耗时、换乘、时间、步行、线路全部小字平铺，扫一眼抓不到重点。
  • 详情时间轴弱：分段依赖缩进文字，线路颜色没有贯穿到时间轴结构。
  • HUD 信息松散：提示行与操作提示缺少"列车在哪、下一步做什么"的空间表达。

二、设计目标

  • 导视优先：像车站导视系统（PIS）一样，用线路色和大数字承载主要信息，一眼可扫。
  • 三级工具收编：主操作（查询／开始导航）唯一且醒目；目录、定位、步行换乘降级为轻量字签。
  • 票卡式方案：每个方案是一张带线路色边的"车票"，大号耗时数字 + 换乘点 + 线路徽章，选中用黄铜包角（保留品牌记忆）。
  • 时间轴贯穿线路色：乘车段的轨道、节点、徽章同色；步行换乘独立为绿色节点卡。
  • HUD 进度化：导航框加一条"轨道 + 列车位置"进度条，下一站与操作提示分层。

三、逐屏改动

  • 换乘查询：标题栏改分段页签；起终点改为"大站名票根"式输入区；结果区左票卡右时间轴；底部主操作"开始导航"通栏化。
  • 车站到发：按线路分组，行内大号倒计时 + 终点 + 站台签 + 实时／计划标记；点击行内联展开提醒设置，不再弹层。
  • HUD：导航框 = 轨道进度 + 下一站大字 + 线路/方向副行 + 黄铜操作提示；提醒框收起态单行化（徽章 + 站名 + 倒计时），展开补方向与站台。

四、Minecraft 可实现性对照

  • 全部元素 = 平色填充 + 1px 描边 + drawString：对应现有 NavigationTheme.outline / fill / text，无需贴图资源。
  • 黄铜包角 = 两条 2px fill；线路色徽章 = 填充 + 深色文字；分段页签 = 描边 + 底部 2px 强调线。
  • 三套皮肤（原版灰／青灰导视／黄铜暗夜）只换令牌与描边，不增加渲染分支。原版灰复刻 MC 原生容器：#C6C6C6 面板、黑描边、白亮边＋深暗边斜面按钮（悬停泛蓝、文字变黄）、黑底输入框、选中行白底。
  • 功能、交互流程、文案与现有版本完全一致，仅重排视觉层级。

五、迭代记录

  • v2.2：新增"原版灰"皮肤并设为默认；按钮按下态（下沉 + 斜面反转）；原版风格滚动条；查询空态页（像素线路示意 + 引导文案，不放空白列表）；票卡补发车时间与"最快／少换乘"标记；时间轴加右对齐时间列；到发分组头加"下一班"摘要、临近班次金色高亮；HUD 轨道加起终点标签。
  • v2.3：新增"拟真渲染"开关（默认开）：接入开源中文像素字体 Fusion Pixel（CDN 加载，离线自动回退）；MC 式实心文字投影（白字 #3F3F3F 影）；按钮改 4 段硬边明暗纹理模拟 widgets.png 离散色阶；黑描边与容器斜面加厚；滚动条加粗。仅作用于原版灰皮肤。
