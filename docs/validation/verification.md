## 实际限制

兼容路径依赖 MTR 原生系统地图服务可用；地图时刻数据不暴露车辆实例及完整班次身份，故不自动确认乘车进度，也不将其路线估算标成实时预测。

当前实测不是大型真实网络的性能成绩；不宣称预知信号拥堵、临时人工驾驶或未来取消。没有进行地图区间高亮或更改 Overlay 的现有渲染。

Fabric 安装包构建及目标 MTR Core 回归通过。Fabric 游戏启动停留在资源加载阶段，尚未完成其世界内界面验证；未完成两个加载器的独立专服完整实测。

## 2026-10-25：单班次到站提醒与顶部通知条

到发列表的单个班次可点击，进入提醒设置，默认提前九分钟，可调节为 1～60 分钟。仅有一个活动提醒，替换其他班次时按钮明确写为替换；取消提醒与取消导航互相独立。普通行程 HUD 保留，另有顶部中央的紧凑通知条，设置和触发时展开约六秒后收起，触发播放一次本地提示音。

核验两个目标 MTR JAR 的 `ArrivalResponseSchema`：公开到发包含线路、站台、方向、departureIndex、到发时间、deviation、realtime，未提供完整 siding／循环／车辆身份。另核验目标 `Siding.getArrivals` 的字节码：序列化到发时间已加 deviation，不再重复叠加。原生提醒仅跟踪时间条目，以线路／站台／方向／departureIndex 和扣除偏差后的精确计划到发时间组成指纹；重复指纹拒绝确认，不将其宣称为实际车辆身份。专用通道则保留完整 RunKey 和停靠序号。

新的采样时间必须递增；旧响应、旧服务器采样和超过五秒未更新的数据不能使提醒重新变为新鲜。延误时跟随同一条记录，提醒触发后不因再次进入阈值而重复触发，不自动替换为后续班次。
