# 车型、编组与行程图标

主界面查询工具栏的“车型条件”或“更多… → 车型条件”可打开车型选择页。这里列出当前网络中实际车辆和车库计划使用的车型；名称、描述和标签由本地 MTR 资源包解析，服务器只接收所选资源 ID。本地缺少资源时保留 ID，不猜车型。

## 查询方式

- **不限制**：沿用原来的时刻查询与排序。
- **优先乘坐**：优先显示至少一个乘车段包含所选车型的方案，其后保留其他车型的备选。默认允许比无条件最快方案晚到 30 分钟；沿用查询设置中的 15／30／60 分钟或不限。
- **必须乘坐**：只返回至少一个乘车段包含所选车型的方案。其他车型可以作为接驳；允许晚到窗口以最快的符合条件方案为基准。

多选按“任意一个”匹配，最多 16 个资源 ID。一列混合编组中任意一节包含所选 ID 即可，车头与拖车均可选择。条件会保留到当前连接结束，不保存为全局偏好。点击“清空条件 → 应用”恢复普通查询。

筛选在服务端时刻搜索中完成，包括搜索状态与剪枝，能够找到排在普通班次之后的目标车型。优先模式的两次搜索共用时间、操作和展开次数预算；达到上限时尽量保留已有方案并标记结果不完整。

## 类别与具体车型

普通铁路、轻轨、高速铁路读取 MTR **线路类别**；M-Train、SP1900 等名称来自具体车厢的 **车型资源**。线路类别只用于显示，不作为车型筛选条件。线路被设置为高速铁路，并不能单凭这个设置判断实际使用的车辆型号。

详情分别标明“实际编组”“计划编组”或未知。计划编组也参与车型匹配，发车前仍可能被运营者更改。车厢数是完整有序车型 ID 列表的长度；点击“查看编组顺序与车型 ID”可查看每节车厢的顺序和原始 ID。

开始必须车型的导航时会再次检查当前数据；不再符合时提示重新查询。导航中发现后续乘车段的已知编组改变会显示提醒，保留原行程供玩家判断。

## 手机导航式行程链

方案卡片按实际顺序排列“步行分钟数 › 线路色块 + 交通图标”。不会补造车站入口到站台的步行段；仅显示查询中已有的步行连接。长线路名称适当省略，完整线路与换乘信息可在详情和卡片提示中查看；步骤过多时显示省略数量。

交通图标直接引用已安装 MTR 的资源，不复制其图片到本模组：

- 普通铁路与未知铁路细分类别：`mtr:textures/block/sign/train.png`。
- 轻轨：`mtr:textures/block/sign/light_rail_1.png`。
- 高速铁路：`mtr:textures/block/sign/xrl_2.png`。

到发页按线路名称、颜色及类别分组；逐班展示车型和编组来源，查询条件不会隐藏到发班次。导航 HUD 和展开的提醒条增加一行车型／车厢数／来源，收起的提醒条保持单行；边界与双 HUD 避让按扩大后的尺寸计算。

## 旧服务器与数据缺失

新车型查询使用可选 `request_v3` 通道；没有此能力的服务器禁用车型条件，保留已有查询能力。v1／v2 请求、旧响应的默认值及公开地图选择接口 `JourneySelection v1` 保持兼容。

只使用 MTR 原生地图接口时，可显示到发接口已有的车辆信息，但不能可靠地为所有未来班次关联编组，因此不支持车型筛选。有基础设施而没有可乘班次、没有符合车型的班次、车型未知以及计算未完成分别提示，不能开始导航的线路参考仍保持禁用。
