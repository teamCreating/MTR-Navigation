# 步行换乘、更多方案与共享审核

对应开发版 Minecraft 1.21.1 / MTR 4.1.0-beta.2，NeoForge 与 Fabric 共用核心。游戏内完整界面及双完整 Minecraft 客户端验收仍待完成；构建、核心回归和专服协议测试分别记录在[验证记录](validation/verification.md)。

## 查询与导航

新版最多返回五种不同走法。同一路线的不同班次不重复占名额，环线停靠序号、方向、上下车站台与步行连接仍参与区分；连续同线路区间会合并为去重身份，行程本身保留实际乘坐的班次。

最快排序使用到达时间、换乘次数、总步行时间；少换乘排序先比较换乘次数。默认晚到窗口为30分钟，可在“步行换乘与查询设置”切为15、30、60分钟或不限。窗口以本次搜索找到的最快有效到达为基准，不自动放宽，也不为凑数重复班次。计算预算耗尽时保留已找到的结果并标记不完整。

连接旧版 Navigation 服务端时继续使用 v1，最多三个纯乘车方案；新版客户端不会向不支持的服务端发送 v2 或共享操作。没有 Navigation 服务端时，个人连接可用于 MTR 原生客户端查询，但仍要求原生时刻服务可用。

步行规则不会根据地理距离自动生成。它可以连接同站不同站台、两个站，或一侧指定站台。人工时间应覆盖两个端点之间完整的步行，站级规则需要填写保守的站台间估算。下一班上车前只额外计入一次服务端配置的换乘余量，默认30秒。

规则按“服务器已发布、个人、MTR默认连接”逐层匹配，每层先找双侧站台，再找单侧站台，最后找站级规则；同等精度以连接 ID 稳定排序。停用表示该条规则不参与匹配，并非禁止其他有效规则或 MTR 原有连接。

每两个乘车段之间最多使用一条额外步行连接，首尾也分别最多一条；不串联站外步行连接，不生成纯步行方案。步行不增加换车次数。没有可用班次时，线路参考仍可显示已声明的步行，但不能启动班次导航。

行程详情将步行、换乘余量和额外候车分别显示。HUD显示目标、人工预计步行耗时及下一班信息；到达后由玩家点“已到达，继续”。接近目标不代表穿过围墙、进入了正确楼层或站台，也不会自动推进。步行超时、错过原班次或相关规则变化时提示重新查询，由玩家确认替换。

## 个人管理与导入导出

点击“步行换乘”，切到“仅自己”，新建连接。车站及可选站台从当前目录选择，保存时再次核验端点；无稳定原生 ID 的临时站台不供人工绑定，可改用站级规则。

- 步行秒数：10～3600，必须明确填写。
- 名称：最多48个 UTF-16 字符；说明最多256个，不解析格式指令和可点击命令。
- 默认同时保存反向个人连接。它们有不同连接 ID、相同分组 ID，可分别调整；共享建议逐方向提交。
- 当前服务器最多保存512条个人有向连接，每维度最多启用32条。重复端点不能保存。
- 修改、启停、删除个人连接会清除旧查询结果，不自动替换活动导航。

个人文件位于实例 `config/mtrnav/personal/<scope-hash>.json`。多人按服务器地址哈希隔离，单机按世界路径哈希隔离；各连接带维度。文件也保存该服务器范围的发送同意状态和晚到窗口，**不建议把整个个人配置文件当作共享文件发送**。

首次在新版服务端查询中使用个人连接时会询问发送授权。可以选择不发送并继续查询；该选择按本服务器记住，后续可在管理页修改。拒绝后只使用服务器共享和MTR默认连接，不上传个人规则。

导入目录固定为实例 `config/mtrnav/imports`；只读取目录内非符号链接 JSON，最多256KiB、128条。先预览，可切换所选记录的启用状态；未知端点自动停用，重新启用必须通过当前目录核验。确认导入会替换相同 ID 的个人记录，不自动提交共享。

导出位于实例 `config/mtrnav/exports`，只含版本与当前维度的连接，超过128条会拆成多个文件；不含服务器地址、发送同意状态、玩家身份或审核日志。

便携 JSON 示例（建议直接使用游戏内导出，示例站点 ID 需要换成存档中的真实 ID）：

```json
{
  "version": 1,
  "connections": [
    {
      "id": "7cd29178-3254-461d-8d0c-e3d893896c24",
      "groupId": "2bc4033c-6852-4240-b07a-179047eb6731",
      "dimension": "minecraft/overworld",
      "fromStation": "a",
      "fromPlatform": "",
      "toStation": "b",
      "toPlatform": "",
      "seconds": 120,
      "name": "步行换乘",
      "description": "人工确认的通道，耗时包含站台间步行",
      "enabled": true
    }
  ]
}
```

原生对象 ID 是无符号小写十六进制，不能用站名替代；便携格式不允许跨维度连接。不同服务器导入后仍需要核对真实端点及通行情况。

## 提交与审核

服务端也安装新版 Navigation 后，才支持服务器共享、我的提交和审核管理。服务端只有 MTR 或 Overlay 时，这些入口不会把数据经 Overlay 上传。

保存个人连接与“提交共享建议”分开。提交预览展示方向、端点、耗时及说明；服务器检查后仅存为待审核，不参与其他玩家查询。普通玩家只能查看、撤回自己的待审核记录；批准后的修改需要再次提交建议，不能直接改写共享库。

默认 OP 等级2及以上可进入审核管理。管理员可以比较当前发布内容和建议内容，先保存审核修改，再单独批准；拒绝必须填写理由。批准、修改、撤回和删除使用预期修订，旧版本请求被拒绝。管理员可直接删除共享记录，并可确认恢复当前维度的历史已发布版本。

共享库保存成功才递增修订、确认发布并通知其他支持的客户端。客户端按需获取当前维度的分页快照，完整校验后原子替换；不会每秒广播整库。提案状态更新通知作者及相关管理员，重新打开页面可读取持久化结果。

个人连接若用于服务端计算，会先明确征求同意；拒绝时不会自动发送。仅发送当前维度已启用连接的 ID、端点、时间与启用状态，不发送名称和说明；原分组 ID 也不随个人查询发送。服务器仅为该玩家计算，原始规则在查询结束后释放；候选与活动行程只保留在其会话中，断线、取消或会话过期后清理。

## 服务端边界与持久化

- 使用现有游戏连接，操作人身份和权限取自服务器实际玩家，不接受客户端填写作者或审核者。异步保存前再次检查当前连接、权限、修订及最新 MTR 端点。
- 上传最多16KiB，解析前限制 JSON 深度。读取限60次／分钟、突发10次；提交限2次／分钟、突发2次；其他修改限10次／分钟、突发5次。按 UUID 保留限流状态，重连不会刷新额度。
- 每人最多5条待审核，全服最多1000条；七天过期。已结束提案最多保留最近1000条。
- 每维度最多1024条已发布有向连接，每服8192条，达到上限明确拒绝。
- 下载每包压缩后最多256KiB、展开后最多1MiB，分块16KiB、十秒过期；每页最多128条共享连接、25条可见提案。分页尺寸、维度、重复及冲突记录均需校验。
- 普通玩家无权读取全服审核页、批准提案、删除共享或恢复备份。按钮状态只方便操作，不替代服务端权限检查。
- 规则只作为结构化数据处理，不执行说明文字、不接受任意上传路径、不下载 URL、不处理压缩导入文件。

世界内固定目录 `data/mtrnav` 保存共享库与审核状态：

- `library.json`：版本、内部修改代数、发布修订、共享记录与提案。
- `backup-<generation>.json`：发布变更前的有效版本，最多保留十份；界面可恢复当前维度，不覆盖其他维度。恢复后的公开条目使用新修订，避免旧建议覆盖恢复内容。
- `audit.log` 及轮换文件：共享操作的作者 UUID、操作、修订及内容变更，按约1MiB轮换，最多五份；不记录个人查询规则。

写入先在单一后台队列准备临时文件，服务器线程再次验证后原子替换，失败不应用修改。读取损坏时保留原文件并尝试最近有效备份；全部失败则禁用共享库写入与依赖它的 v2 查询，旧版查询不因此改成信任客户端整库。

该权限模型依赖服务器已建立的玩家身份认证，不能补救离线服务器的身份冒用。

## 协议与 Overlay

新增可选 `request_v2` 查询和独立的 `walking_request_v1` / `walking_response_v1` 管理通道。原有 `request_v1` / `response_v1` 保留；新服务器对旧通道只返回旧版纯乘车语义。v2结果增加最快基准、不完整标记、共享步行修订及有序步骤所需数据。

公共地图接口仍为 `JourneySelection v1`，只导出精确乘车区间。相邻区间之间可能有步行，Overlay不能假定连续轨道；本轮不提供地图步行折线接口。详见 [Overlay 对接指南](overlay-integration.md)。

## 开发验证

常规构建及回归：

```powershell
.\dev.ps1 -Platform neoforge build testFabricCore -PtestOverlay --offline
.\dev.ps1 -Platform fabric build --offline
```

专服协议测试工具使用开发依赖 [minecraft-protocol](https://github.com/PrismarineJS/node-minecraft-protocol)，不打包进模组。依赖安装到项目缓存，npm缓存也需指向项目：

```powershell
$env:npm_config_cache = "$PWD\.cache\npm"
npm install --prefix .cache/protocol-bots --ignore-scripts --no-audit --no-fund minecraft-protocol@1.68.0
node tools/walking_protocol_smoke.cjs
```

工具固定连接 `127.0.0.1` 的25586（NeoForge）或25588（Fabric），拒绝其他端口；需要独立测试存档、至少两个MTR站点，以及离线测试账户 NavModerator 的OP等级2。它创建普通申请者、管理员、旁观者三个协议连接，验证审核与实际下发；不模拟渲染、物品界面或完整客户端模组。

Fabric使用 `MTRNAV_TEST_LOADER=fabric`、`MTRNAV_TEST_PORT=25588`。设置 `MTRNAV_TEST_LEGACY=1` 可验证只声明旧版v1通道的客户端。报告位于项目 `build/validation`。每轮应在独立的本机测试专服中运行，不能用于正式服务器。

**仍需完整游戏验收**：双方真实客户端的页面操作、GUI缩放、中文输入、HUD、手动步行、断线及切维度，并分别验证单机、专服与无 Navigation 服务端场景。协议测试通过不等于这些项目已完成。
